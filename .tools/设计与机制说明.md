# 《万界如林》机制 · 数值 · 流派 — 交接说明

> 版本 **v0.4.6** ｜ 游戏 Slay the Spire 2（0.111.0）｜ 依赖 RitsuLib 0.6.2
> 角色：**林**（水墨风自定义角色）｜ 卡池 **89 张**

---

## 一、一句话概括

**「鬼气」是一个会自我惩罚的次级资源。** 攒得越多、爆发越高，但**高鬼气会持续削你的攻击伤害** ——
所以「攒多少、什么时候泄」是每一回合的核心决策。

整套设计围绕这个张力展开，分成三条互斥的流派。

---

## 二、核心机制

### 2.1 鬼气（Ghost Qi）

| 项 | 值 |
|---|---|
| 战斗开始 / 每场战斗重置 | **1** |
| 软上限（UI 显示） | 20 |
| 硬上限 | 99 |
| 每回合自动回复 | **无**（`turnStartPolicy = None`，只能靠卡牌获得） |
| 换算参考 | 1 点鬼气 ≈ 1 点能量（同为资源，但鬼气有「墨浓惩罚」） |

**费用动词用「耗费」**（不是「消耗」）—— 「消耗」是 Exhaust 关键字的官方译名，两者必须区分开。

### 2.2 墨之相（Ink Phase）— 核心张力所在

鬼气数量会**自动改变你的攻击伤害**，这是整个模组的灵魂：

| 相 | 鬼气 | 效果 |
|---|---|---|
| **墨淡** | ≤ 2 | 每回合额外**抽 1 张牌** |
| **墨匀** | 3 – 7 | 无任何奖惩（安全区） |
| **墨浓** | ≥ 8 | **攻击伤害 −2** |
| **墨极浓** | ≥ 14 | **攻击伤害 −5** |

> 设计意图：**高鬼气不是免费的**。你可以囤到 14+ 换取超模的爆发卡，但同时所有攻击都在掉伤害，
> 必须尽快把鬼气倾泻出去（或用「耗鬼气」的卡收尾）。
> 反过来「墨淡」给抽牌 —— 鼓励 L 流主动清空鬼气。

### 2.3 三条流派（靠**硬条件互斥**锁死，不能混搭）

| 流派 | 鬼气区间 | 玩法 | 关键卡 |
|---|---|---|---|
| **H 蓄鬼** | ≥ 4 / ≥ 8 / ≥ 10 / ≥ 14 | 攒鬼气 → 用高阈值卡爆发 → 清空 | 墨龙、一画开天、悠悠电龙、傲慢 |
| **L 蜕鬼** | = 0 / ≤ 2 / ≤ 3 | 主动清空鬼气 → 触发「低鬼气奖励」 | 蜕鬼、素心一剑、空明、阳光普照、淡墨 |
| **M 匀墨** | 3 – 7 之间 | 把鬼气**维持**在安全区，靠「区间引擎」滚雪球 | 尸瞳、半砚、墨韵天成、鬼气循环 |

**互斥是硬条件**（`PlayCondition`），比如「鬼气 = 0」和「鬼气 ≥ 12」永远不可能同时满足 ——
所以玩家必须**早早选一条路走到底**，这是构筑深度的来源。

### 2.4 v0.4 新增的四个机制

| 机制 | 效果 | 代表卡 |
|---|---|---|
| **连笔** | 本回合内，你每打出一张牌，本回合伤害 **+2**（上限 4 层／升级 6） | 挥毫（普通）、笔走龙蛇（稀有 +3/层 上限 5） |
| **血墨** | 用**生命**换强度（自伤可被格挡吸收） | 消火、大梦一场、血墨淋漓（4 血换 16）、沥血（0 费 6 血换 20） |
| **伏笔** | 打出后**不立即生效**，N 回合后对所有敌人引爆 | 埋锋（2 回合后 14 伤）、十日后（3 回合后 30 伤） |
| **相位天气** | 每回合随机降下一种墨相（格挡／鬼气／能量） | 天时（强度 5）、墨相流转（强度 8） |

## 三、数值基线（★ 全部对齐原版）

**这是「强度是否合理」的唯一尺子。** 从原版 596 张卡的数据统计出来的中位数：

### 攻击牌 · 单段伤害

| 费用 | 普通 | 罕见 | 稀有 |
|---|---|---|---|
| 1 费 | **7** | **9** | 9 |
| 2 费 | **8** | **13** | 11 |
| 3 费 | 27 | **22** | 19 |

### 技能牌 · 格挡

| 费用 | 普通 | 罕见 | 稀有 |
|---|---|---|---|
| 1 费 | **6** | 7 | 5 |
| 2 费 | 11 | 11 | 21 |
| 3 费 | — | 13 | — |

> ⚠️ **历史教训**：本模组早期按「2 费 15–18 伤害」设计，**比原版（8–13）高出一大截**，
> 玩家反馈「强度不对劲」就是这个原因。v0.4 已全部下修到上表。
> **改数值时请对照这张表，不要凭感觉。**

### 费用分布（原版参考）

| 稀有度 | 0 费 | 1 费 | 2 费 | 3 费 |
|---|---|---|---|---|
| 普通 | 21 | 75 | 14 | 1 |
| 罕见 | 55 | 130 | 45 | 13 |
| 稀有 | 31 | 64 | 42 | 29 |

**1 费是绝对主力**，2 费要明显更重，3 费是终结技。

## 六、一局的节奏（玩法循环）

```
战斗开始：鬼气 = 1（墨淡区）
   ↓
前几回合：用「产气牌」（宿墨/研墨/墨点）把鬼气堆到目标区间
   ↓
关键转折：鬼气 ≥8 后攻击开始掉伤害（墨浓惩罚）
   ↓
要么：继续堆到 14+ → 打出 H 流终结技（一画开天/傲慢）→ 清空
要么：主动清空 → 触发 L 流奖励（蜕鬼/素心一剑）
要么：稳在 3-7 → M 流引擎每回合稳定收益
   ↓
战斗结束：鬼气重置回 1（不跨战斗继承）
```

**核心决策**：每一回合都在「多攒一点」和「现在就用掉」之间做取舍。

## 七、接手修改指南（工程侧）

### 目录

```
WanJieRuLin/            ← 游戏资源（卡图/能力图/场景/本地化 json）
WanJieRuLinCode/        ← C# 源码
  Cards/                ← 89 张卡的实现（由生成器产出，别手改！）
  Powers/               ← 能力
  Characters/           ← 角色 + 卡池
.tools/                 ← ★ 真相源脚本
  gen_*.py              ← 卡牌生成器
  card_loc_v04.py       ← ★ 卡牌文案（唯一真相源）
  gen_loc.py            ← 本地化生成
  audit*.py             ← 6 项自动审计
  package.py            ← 打包（含自动发布）
```

### ★★ 三条铁律

1. **不要手改 `Cards/*.cs`** —— 它们由生成器产出，下次生成会覆盖。
   改卡请改生成器的规格。
2. **文案改 `.tools/card_loc_v04.py`**，不要改 `localization/*.json`（会被覆盖）。
3. **数值改动必须对照第三章的原版基线。**

### 改完必跑

```bash
python .tools/gen_cards_v04.py       # 重新生成卡
python .tools/gen_loc.py             # 重新生成文案
python .tools/audit.py               # 综合审计
python .tools/audit_infinite.py      # 反无限检查
python .tools/audit_ghostqi.py       # 鬼气费用检查
python .tools/audit_placeholders.py  # 占位符检查
```

**4 项审计全过才算改完**（历史上「静默失效」的 bug 全靠它们抓出来）。

### 打包发布

```bash
python .tools/package.py    # 打包 + 自动上传最新安装包到 GitHub
```
产物输出到桌面 `WanJieRuLin-dist/`，并自动推送到 GitHub 的 `dist` 分支。

## 八、已知问题 / 建议改进方向

### 需要实测验证的（数值手感未经真人对局检验）

1. **连笔**（挥毫/笔走龙蛇）—— 每打一张牌 +2 伤害，上限 4/5 层。
   实际能不能轻松叠满？叠满后是否过强？（这是全模组最高的单回合天花板）
2. **血墨**性价比 —— 沥血「0 费 6 血换 20 伤」是否过强？自伤被格挡吸收是否符合预期？
3. **伏笔**的延迟收益 —— 3 回合的等待值不值 30 点伤害？会不会太慢？
4. **相位天气**的随机性 —— 会不会太看脸？

### 结构性可改进点

- **三流派目前偏「自闭」**：互斥条件锁得很死，跨流派的桥接卡几乎没有。
  可以考虑加 1–2 张「切换流派」的过渡卡，增加构筑变化。
- **H 流的墨浓惩罚**（≥8 攻击 −2）在实战中是否足够痛？如果玩家感觉不到，
  惩罚需要加重或改形态。
- **墨极浓（≥14）** 门槛很高，目前只有 3 张卡用到（一画开天、傲慢、悠悠电龙），
  可以考虑再补 1–2 张，让这条极端路线更成型。
- **遗物只有 5 个**，相对卡池规模偏少，是明显的内容缺口。
- 敌人 / 事件未做改动，仍是原版内容。

### 已知的工程坑（接手时注意）

- **删卡会破坏存档** —— 玩家牌组里引用已删卡类时，游戏会显示「弃用卡牌」占位符。
  要删卡请提醒玩家开新档，或在发行说明里写明。
- **卡池 `SkillCardTypes` 是手写 `typeof()` 清单**，增删卡必须同步，否则编译失败。
- **「本回合」能力不会自动消失** —— 必须继承 `WanJieTurnScopedPower` 基类。
- **临时能力的 `OriginModel` 不能指向自身**（无限递归，零异常硬死机）。
- 改完 DLL **必须完全退出游戏再重开**（RitsuLib 只在启动时加载）。

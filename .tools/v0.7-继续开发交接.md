## 二、v0.7 规格（用户原话逐条）

> 万界如林卡牌限制（**能力牌不在范围之内**）  
> 能力牌之外的攻击牌、技能牌获得前缀（「点：」「线：」「面：」）

### 点（费用固定 0–1）· 机制「斑驳乱点」

- 打出会累积乱点；**点打出越多（三张之内无损耗）**，本回合获得的负面效果越多，直到玩家无法承受
- 例：降低攻击/敏捷、获得虚弱/易伤、消耗某些卡、**将诅咒卡塞入弃牌堆**
- **下回合会清空负面效果**

> ★ 用户补充：「塞诅咒就是把诅咒牌放入弃牌堆，**用杀戮尖塔原有的诅咒卡**就可以，  
> 你这个循环代价太低，**还要增强负面效果**」

### 线（费用固定 1–2）· 机制「千钧一线」

- 打出后本回合获得**临时力量和临时敏捷**，**抽 1 张牌**
- **所有线卡都包含抽一张牌效果**（原本抽 4 张的牌，变抽 5 张）
- **线卡的攻击牌和技能牌都拥有不止一个效果**（伤害、格挡、抽牌、易伤、虚弱…）

> ★ 用户明确：**不要压低线牌数值，「依旧让他数值正常」**

### 面（费用固定 2–6）· 机制「去年今日此门中」

- 数值效果等极高，因此需要大量费用打出
- **所有面牌均为消耗牌**
- 打出之后会**将一张这张牌的 0 费版本放入弃牌堆**
- **该效果每场对战只能作用一次** → 用户确认是 **「每张面牌各一次」**

### 玩法目标

> 万界如林可以通过点线面的交加，打出相当不错的配合，例如通过线来增强当前回合的临时数值，  
> 从而再用点打出比较不菲的伤害，又或者用点付出代价的情况下可以打出高费用的面。  
> 希望让玩家拥有更多可玩性，并**提高决策效果**。

### 能力牌设计方向

- 支撑「**只选点/只选线/只选面**」的三流派（只抓一类牌，靠能力让这一类有相当好的效果与体验）
- **加强卡牌之间的紧密联系**，让点线面在游戏中表现得更为强力
- **效果交由你设计**

### 初始牌 / 遗物

> 「初始牌拥有点线面各一张，并且这三张牌都可以与之后所抽到的点线面进行不错的 combo」  
> 用户确认：**「其中两张为攻击，一张为技能」**

### ★★ 升级设计要求（重要）

> 「你的升级只提升数值并不合适，**最好提升一些卡牌相应的效果，而不是只提升造成的伤害以及获得的防御**」

用户确认：**全部 90 张都要做「效果升级」**，不是只提数值。

## 六、★★★ 技术要点与踩过的坑（最值钱的部分）

### 6.1 造牌的正确姿势（面的回流要用）

```csharp
var canonical = ModelDb.Card<X>();          // 或 Activator.CreateInstance(type)
var created = canonical.ToMutable();        // ★ 必须 ToMutable，否则 CanonicalModelException
created.Owner = player;                     // ★ 必须设 Owner
await CardPileCmd.AddGeneratedCardToCombat(created, PileType.Discard, player, CardPilePosition.Random);
```

**不要手工克隆、不要 CreateCloneForPlayer** —— 会 `NullReferenceException`（牌没有堆）。

### 6.2 ★★★ 钩子分三类，不能类推

| 类型                                                                                                                                                                            | 能不能用                                                                                                                    |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **原版普通 virtual**（`AfterCardPlayed` / `ModifyDamageAdditive` / `ModifyBlockAdditive` / `AfterPlayerTurnStart` / `BeforeCardPlayed` / `AfterSideTurnEnd` / `BeforeCombatStart`） | ✅ 直接 `override`                                                                                                         |
| **原版 `private protected` virtual**（`TryModifyEnergyCostInCombat` —— 费用修改）                                                                                                     | ❌ **模组无法 override**（CS0115）。原版能力能重写，我们不行。只能改用公开运行时 API（如 `CardEnergyCost.AddUntilPlayed`）或换设计                           |
| **RitsuLib 的 `I*Contributor`**                                                                                                                                                | ⚠️ **要逐个确认**。`ICardPlayStateContributor`（可打出条件）是「实现即生效」；`ICardEnergyCostContributor` **不是**（需显式 AddCapability），实测减费从未生效 |

**找可重写方法时**：去 `_scratch/sts2-mod/dumps/peek41.txt` / `peek50.txt` 查**精确签名**  
（带参数类型与 `[virtual]` 标记）。`_all.txt` 有全量成员。

### 6.3 `BeforeCardPlayed` 的用法（面的强化要用）

```csharp
public override Task BeforeCardPlayed(CardPlay cardPlay)   // ★ 注意：没有 PlayerChoiceContext
```

→ 只能打标记；真正的数值加成要靠 `ModifyDamageAdditive` / `ModifyBlockAdditive`。  
**不能在里面 await 施法**（没有 context）。

### 6.4 「本回合」的能力必须继承 `WanJieTurnScopedPower`

否则回合结束**不会自动消失**。`PowerStackType` 里没有 Duration。

### 6.5 其他硬性规则

- **`WanJieRuLinCode` 是 `WanJieRuLin` 的兄弟目录**（不是子目录）
- **卡牌基类是 `WanJieRuLinCardModel`**，在 `Cards/` 下；子类只需重写 `Aspect` / `OnPlay` / `OnUpgrade` / `CanonicalVars`
- **`Owner` 在卡牌/能力里是 `Creature`**（要 `Owner.Player` 拿 Player）；  
  **在遗物里 `Owner` 直接就是 `Player`** ★（照抄会编译错）
- **类名不能和命名空间同名**（先古卡因此叫 `WanJieRuLinAncient`）
- 本地化键 `WAN_JIE_RU_LIN_{TYPE}_{类名大写下划线}`
- 卡图 `res://WanJieRuLin/images/cards/{类名}.png`
- **改完 DLL 必须完全退出游戏再重开**（RitsuLib 只在启动时加载）
- **删卡会破坏存档** —— 玩家牌组引用已删卡类时会变成「弃用卡牌」占位符

### 6.6 改了卡名/删了卡之后

**必须重建 `Characters/WanJieRuLinCardPool.cs` 的 `SkillCardTypes`** ——  
它是**手写 `typeof()` 清单**，不同步就编译报「类型不存在」。  
可用 `_scratch/sts2-mod/_v05_pool.py` 的思路从生成器规格自动重建（**注意要在所有改名完成之后跑**）。

## 八、卡牌规格 DSL（生成器里怎么写）

```python
card('类名', '中文名', 费用, '类型', '稀有度', '目标',
     aspect='Point',                  # 点/线/面
     ex=True,                          # [消耗]（面牌全都要）
     cond='LiDaoAtLeast(5)',           # 可打出条件（可选）
     vars_=[DV % 伤害, BV % 格挡, vc(抽牌), vr(段数), vi('命名变量', 值)],
     play=[...出牌逻辑...],
     upg=['...升级逻辑...'],           # ★ 要做「效果升级」，不是只加数值
     doc='★ **点** —— 效果描述。升级后 ……。')
```

**`doc` 的格式要求**（文案生成器靠它自动提取）：  
`★ **类** —— 效果正文。升级后 …。`  
★ **破折号（——）之后的才是效果正文**，之前的会被当设计注丢掉。

**改数值后必须同步 doc 里的数字** —— 文案生成器靠**数字匹配**插入占位符，  
数字不同步会匹配失败、卡面显示死数字。脚本：`_scratch/sts2-mod/_v06_docsync.py`。

## 九、90 张卡的设计要点（建议）

- **点**：费用 0–1，数值可以正常（用户不要求压低），但**每张都应该有「乱点」的自觉** ——  
  低费高频，靠数量堆收益，超过 3 张开始自伤
- **线**：费用 1–2，**数值正常** + **必须额外抽 1** + **必须不止一个效果**  
  （伤害+格挡、伤害+易伤、格挡+虚弱+抽牌…）
- **面**：费用 2–6，数值极高，**全部 [消耗]**，**每张都有 0 费回流版本**（每场一次）
- **升级**：全部做**效果升级**（加关键字、加目标、加触发、改机制），不是单纯 +数值
- **能力牌**：三流派（纯点/纯线/纯面）+ 三类联系（如「你打出点牌时，本回合的线牌 +1 数值」）
